# 사회사업실 원스탑 서비스 — 디자인 기준서 (적용 기준)

> 이 문서는 **지금 화면에 실제로 적용된 디자인**을 정리한 것입니다. 값의 출처는 `public/style.css` 맨 위 토큰입니다.
> 처음 받은 `DESIGN_GUIDE.md`(소프트 UI)를 바탕으로 하되, 이 프로그램의 사정(고령 직원, 병원 PC)에 맞춰
> 달라진 부분은 [9. 원래 기준서와 다른 점](#9-원래-기준서와-다른-점)에 모아 두었습니다.
> 화면을 고칠 때는 이 문서의 토큰과 컴포넌트를 그대로 쓰고, 없는 값을 임의로 만들지 마세요.

- 콘셉트: **소프트 UI** — 라벤더 그레이 배경 + 흰 카드 + 보라 그라데이션 포인트(핑크는 보조)
- 기준 폭: 모바일 우선(375px). 태블릿·데스크톱은 [4. 레이아웃](#4-레이아웃)을 따릅니다.
- 쓰는 사람: 50~60대 직원이 많습니다. 글씨는 크게, 대비는 확실하게.

---

## 0. 필수 규칙 7가지

1. **색·크기·간격·라운드·그림자는 토큰(CSS 변수)만 씁니다.** 코드에 `#7E5DB4`, `12px` 같은 값을 직접 적지 않습니다.
2. **강조색(보라 그라데이션)은 한 화면에 1~2곳만.** 선택된 항목, 주 단추, 점수 카드, 담당자 사이드바의 현재 메뉴.
3. **구분선으로 영역을 나누지 않습니다.** 흰 카드와 배경의 밝기 차이 + 옅은 그림자로 나눕니다. 표는 줄무늬.
4. 모든 화면은 **머리글 → 가운데(스크롤) → 아래 고정** 3단 구조입니다.
5. 글자 색은 **진한 색(`--text-primary`) / 회색(`--text-secondary`)** 두 단계만. (색 면 위 흰 글자 제외)
6. 글자 굵기는 **400·500·600만**. 700 이상은 쓰지 않습니다.
7. 글자 크기는 줄이지 않습니다. (고령 직원 때문에 기준서보다 한 단계 키워 둔 것입니다.)

## 1. 디자인 원칙

| 원칙 | 적용 방법 |
|---|---|
| 강조는 컬러 블록 하나로 | 나머지는 흰 카드 + 회색 글자. 컬러 카드가 한 화면에 3개 이상이면 다시 생각합니다. |
| 선 대신 면과 그림자 | `border`는 입력칸 포커스·오류와 상태 표시(왼쪽 색 줄)에만. |
| 큰 라운드 | 카드·단추 18px, 입력칸·칩·아이콘 박스 12px, 배지 8px, 원형은 아바타·점·아이콘 단추. |
| 넉넉한 여백 | 좌우 20px, 요소 사이 12~16px, 구역 사이 24px. |
| 일관된 하단 | 직원 화면은 아래 탭바, 입력 화면은 탭바 대신 전폭 단추. |

## 3. 글꼴

- **Noto Sans KR** (가변 글꼴, SIL Open Font License) — 기준서의 Pretendard 대신 담당자가 정했습니다.
- 대체 순서: `'Noto Sans KR', 'Malgun Gothic', 'Apple SD Gothic Neo', system-ui, sans-serif`
- 파일은 `public/fonts/noto-sans-kr/` 에 들어 있고 `public/fonts/noto-sans-kr.css` 가 불러옵니다.
  **바깥 주소로 받아오지 않으므로** 인터넷이 없는 병원 PC에서도 같은 글꼴로 보입니다.
  글자 영역별로 쪼개져 있어 화면에 쓰이는 조각만 내려받습니다(보통 200KB 안팎).
- 한글 줄바꿈은 `word-break: keep-all`. 카드 제목은 2줄까지 보이고 말줄임(`-webkit-line-clamp:2`).
- (체험판 HTML 한 장에는 글꼴이 들어가지 않아 시스템 글꼴로 보입니다.)

## 4. 레이아웃

### 4-1. 3단 구조

```
┌──────────────────────────┐
│ 머리글 (56px, 고정)        │  .hdr
├──────────────────────────┤
│ 가운데 (세로 스크롤)        │  .scroll-area > .page  (좌우 20px, 최대 폭 720px)
├──────────────────────────┤
│ 아래 고정                  │  .tabbar (64px) 또는 .bottom (전폭 단추)
└──────────────────────────┘
```

- 스크롤은 **가운데만**. 머리글과 아래 영역은 움직이지 않습니다.
- 화면 맨 아래에는 항상 **MISSION** 이 들어갑니다 — *어르신은 건강하게, 가족은 편안하게, 직원은 즐겁게*

### 4-2. 반응형

| 구간 | 규칙 |
|---|---|
| 모바일 (< 1100px) | 이 문서 기본값. 담당자 화면은 위쪽에 메뉴 칩(`.mtabs`)이 가로로 놓임 |
| 데스크톱 (≥ 1100px) | 담당자 화면에 **왼쪽 사이드바**(`.side`, 240px), 가운데 최대 폭 1200px. 위쪽 메뉴 칩과 머리글은 숨김 |
| 520px 이하 | 두 칸짜리 입력(`.frow`)이 한 칸으로 |

확인 폭: **375 · 768 · 1280px 에서 가로 스크롤이 생기지 않아야 합니다.**

## 6. 상태 규칙

**한 줄 원칙: 선택·활성 = 보라, 나머지 = 흰색 / 회색 면.**

| 요소 | 기본 | 선택·활성 | 눌림 | 포커스 | 비활성 | 오류 |
|---|---|---|---|---|---|---|
| 칩 | 회색 면 + 회색 글자 | 보라 + 흰 글자 + 600 | 밝기 97% | 2px 보라 윤곽 | 흐리게 | — |
| 입력칸 | 회색 면 | — | — | 흰 바탕 + 1.5px 보라 | 글자 `--text-disabled` | 1.5px 핑크 + 아래 안내 |
| 주 단추 | 그라데이션 | — | 밝기 92% | 2px 보라 윤곽(간격 2px) | 40% 흐리게, 누를 수 없음 | — |
| 목록 항목 | 흰 카드 | 2px 보라 윤곽 | 살짝 작아짐(scale .99) | 2px 보라 윤곽 | 지난 것 62% | — |
| 아래 탭 | 회색 | 진한 글자 + 보라 아이콘 + 점 | — | 2px 보라 윤곽 | — | — |

- **상태를 색만으로 구분하지 않습니다.** 선택은 굵기(600), ✓, 점 같은 표시를 함께 씁니다.
- 포커스 윤곽은 모든 눌리는 요소에 보여야 합니다(`:focus-visible`).

## 7. 접근성

| 항목 | 기준 | 지금 값 |
|---|---|---|
| 일반 글자 대비 | 4.5:1 이상 | 진한 글자/배경 14.4:1 · 보조 글자/흰색 5.0:1 · 오류 글자/흰색 5.8:1 · 보라 글자/흰색 5.1:1 |
| 그라데이션 위 흰 글자 | 밝은 쪽 기준 확인 | 밝은 쪽 `#8E6BBF` **4.2:1**(기준 미달, 기준서 값 그대로 유지) · 어두운 쪽 6.3:1 · 단색 `#7E5DB4` 5.1:1 |
| 보조 글자/앱 배경 | — | **4.3:1**(배경이 연보라라 흰 바탕보다 낮음). 작은 글씨는 흰 카드 안에 두는 것을 권장 |
| 터치 영역 | 44×44px 이상 | 아이콘 단추·탭·작은 단추 `.btn.xs` 는 34px(표 안 보조 용도) |
| 아이콘 단추 | `aria-label` 필수 | 머리글·탭바 단추에 적용 |
| 폼 | `<label>` 연결 | 입력칸마다 `for` 연결 |

> 대비가 기준에 못 미치는 두 곳(밝은 보라 위 흰 글자, 연보라 배경 위 보조 글자)은 기준서 값을 그대로 쓴 결과입니다.
> 개선이 필요하면 `--color-primary-start` 를 조금 어둡게, `--text-secondary` 를 조금 진하게 바꾸면 됩니다(토큰 한 줄).

## 10. 작업 체크리스트

화면을 고치거나 새로 만들 때 확인합니다.

- [ ] 색·크기·간격·그림자를 토큰으로만 썼다 (코드에 `#xxxxxx` 직접 적지 않음)
- [ ] 강조색(그라데이션) 요소가 한 화면에 1~2개다
- [ ] 구분선 대신 면·그림자로 나눴다
- [ ] 머리글 → 가운데 스크롤 → 아래 고정의 3단 구조다
- [ ] 글자 크기를 줄이지 않았고, 굵기는 400~600이다
- [ ] 선택·눌림·포커스·비활성·오류 상태를 모두 만들었다
- [ ] 빈 상태와 로딩 상태가 있다
- [ ] 눌리는 요소가 44px 이상이고 아이콘 단추에 `aria-label` 이 있다
- [ ] 375 · 768 · 1280px 에서 가로 스크롤이 생기지 않는다
- [ ] **화면에 나오는 글을 바꿔야 한다면 먼저 담당자에게 확인받았다** (병동 초과 안내 문구는 특히 그대로)
- [ ] `lib/rules.js` 와 `public/demo.js` 짝을 맞췄다 / `node tests/demo.test.js` 28건 통과

### 새 값이 필요할 때
1. 기존 토큰으로 되는지 먼저 확인합니다.
2. 안 되면 `style.css` 맨 위 "추가 토큰" 칸에 **이름과 이유를 주석으로** 적어 추가합니다.
3. 이 문서 [2-3](#2-3-기준서에-없어서-추가한-값)과 [9](#9-원래-기준서와-다른-점)에도 한 줄 적고 담당자에게 알립니다.
