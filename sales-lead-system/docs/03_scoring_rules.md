# 필요도(A/B/C) 산출 규칙 — 현재 휴리스틱 (src 구현과 동일)

"필요도" = 미아 발생 위험 × 도입 실행 가능성 × 1회 제안 파급력.

## 관리기관 단위 (도시공원 데이터, src/ingest_parks.py)
- 물놀이 관련 공원: 시설 항목 또는 공원명에 `물놀이|워터|수영|바닥분수|아쿠아|water` (분수·계류·실개천은 조경이라 제외)
- 대형 공원: 근린·수변·역사·문화·체육공원
- A: 물놀이 ≥3, 또는 물놀이 ≥1 이면서 대형 ≥15
- B: 물놀이 ≥1, 또는 대형 ≥15, 또는 공원 ≥100
- C: 나머지
- 정렬 점수: min(대형,30) + 8×min(물놀이,5) + 0.1×min(유희시설공원,100) + 0.1×min(공원수,100)
- 결과: A 48 / B 109 / C 175 (총 332)

## 민간 테마파크 (src/ingest_themeparks.py)
- A: 시설면적 ≥3,000㎡, 또는 물놀이 업체(전화 있음), 허가 대형 파일은 물놀이·대형 브랜드
- B: 물놀이/리조트, 면적 ≥1,000㎡, 놀이시설 ≥5종, 키즈·실내
- C: 이동식·행사성, 그 외
- 결과: 일반 A 53 / B 76 / C 263, 허가 A 42 / B 13

## 한계와 개선 과제
- 이름 기반 유형 추정(오탐 가능). 예: 공원명에 '수영'이 들어간 어린이공원.
- 면적·방문객 데이터 부재. 실제 방문객 수(관광지 입장객 통계), 유료 입장 여부, 운영 주체 규모를 추가하면 정확도 향상.
- 등급 규칙을 설정(YAML)으로 분리하고, 수동 보정(override) 필드를 둘 것.
