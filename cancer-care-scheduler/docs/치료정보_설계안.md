# 환자 치료정보 구조화 설계안 (초안 v1 — 배포 전 검토용)

> 목적: 환자명부의 치료정보(현재 자유 텍스트)를 **항목·횟수·옵션이 구분되는 구조**로 입력하고, 환자명부에는 **요약**으로 표시한다.
> 상태: 설계·검증 단계. 앱에는 아무것도 반영하지 않았다.

## 1. 현재 표기 분석 (실제 60건 기준)

### 1-1. 항목 약어 사전
| 정식 항목 | 현장 표기(관찰됨) | 종류 |
|---|---|---|
| 고주파 BSD | 고BSD, 고주파(BSD) | 횟수형 |
| 고주파 온코 | 고(온), 고(온코), 고온, 고주파(온코) | 횟수형 |
| 싸이케어 주사 | 싸이 | 횟수형 |
| 이뮤알파 주사 | 이뮤 | 횟수형 |
| 압노바 A/M/F/Q (1~4단계) | 압A, 압F, 압Q4, 압M2, 압F3단계, 압F(4단계) | 횟수형 + 종류 + 단계 |
| 이스카도 Q (1~3단계) | 이스카, 이스, 이스카Q | 횟수형 |
| 메시마 / 메시마F | 메, 메F, 메시마, 메시마F + `N포` | **수량형(포)** |
| 건칠단 | (샘플에 없음) | 수량형 추정 |
| 페인잼머 + 후속치료 | pj, PJ, 페인잼머 + `도수·림프·파동·역박동` | 횟수형 + 후속 |
| 지씨타치온 | 지씨타, 지씨타치온 | 횟수형 |
| 영양제(라보솔·콤비플렉스) | 영양제, 라보솔, 콤비 | 횟수형 |
| 메리트씨 주사 | 메리트, 메리트씨 | 횟수형 |
| 나드정 / 피도큐산 | 나드정60정, 피도큐산28포 | **수량형(정·포)** |
| 고압산소 | 고압산소 | 횟수형 |
| 목록에 없던 것 | 파동, 역박동(단독), VC10V, 글루치온정, 구치온2V | 항목 추가 검토 |

### 1-2. 표기 문법
- **횟수**: `주N` = 주 N회, `(월N)`·`월N회` = 월 N회 총량, `격주N` = 2주에 N회, `총N회` = 기간 총 N회. 보통 `주2(월8)`처럼 둘을 같이 적는다(월 = 주×4가 기본, 예외 있음: 월7·월9·월10·월5·월6).
- **옵션**: 항목 뒤 `S`(서비스)·`서비스`, `K`(연기 수령, 예: `월4K`·`림1k`). 옵션 없음 = J(기본).
- **수량**: `90포`, `60정`, `10V`. 월 횟수가 아니라 **총량**.
- **페인잼머 후속치료**: `pj주3(월12) 도1,림2` — 페인잼머 1회마다 뒤따르는 후속치료. 숫자 합이 주 횟수와 같으면 주 기준(`pj주3 → 도1+림2`), 월 횟수와 같으면 월 기준(`pj(월6회)도4,림2`).
- 구분자는 `+`가 기본이나 공백·쉼표·`*`로도 이어 붙인다(예: `…(림프2,도수2)*영양제 월1(서비스) 파동 주1(월4)서비스`).
- 자유 메모 섞임: `26.11/24통원 치료유지`, `*항암후만`, 오타 `(얼7)`.

## 2. 데이터 구조

### 2-1. 치료항목 사전 `treatment_catalog` (관리자가 추가·수정, 배포 불필요)
`code, name(정식명), short(약어·요약 표기), kind('session'|'qty'), variants[], stages[], unit('포'|'정'|'V'), followable(후속치료 가능 여부), sort, active`

### 2-2. 환자별 치료 계획 `patients.treatments` (jsonb 배열 — 환자 저장과 한 번에 처리, 일일 스냅샷에도 그대로 포함)
```json
[
 {"code":"hf_onco","perWeek":2,"perMonth":8},
 {"code":"abn","variant":"F","stage":4,"perWeek":2,"perMonth":8},
 {"code":"mes","qty":90,"unit":"포"},
 {"code":"pj","perWeek":3,"perMonth":12,
  "follow":[{"item":"도수","n":1},{"item":"림프","n":2}],"followBasis":"week"},
 {"code":"wav","perMonth":4,"option":"S"}
]
```
- 항목별 선택 필드: `perWeek / perMonth / everyOtherWeek / total / qty+unit / option(S·K·C) / note`.
- `patients.plan`(기존 텍스트)은 **요약 문자열로 자동 생성**해 계속 채운다 → 기존 화면·CSV·스냅샷·검색이 그대로 동작.
- `patients.plan_raw`: 이전 원문을 보존(되돌리기·대조용).
- 별도 테이블이 아니라 jsonb를 택한 이유: 환자 1명당 항목 5~10개, 활성 환자 약 60명으로 규모가 작고, 환자 저장·스냅샷·복원과 한 묶음으로 움직여 일관성이 쉽다. 항목별 통계는 jsonb 질의로 충분.

### 2-3. 환자명부 요약 표시 규칙
`고(온)주2 · 싸이주1 · 압F4 주2 · 메시마90포 · PJ주3(도1·림2) · 파동월4S`
- 현행 표기와 비슷한 길이/모양(1~2줄). 마우스를 올리거나 정보창을 열면 항목별 상세 표.

## 3. 입력 화면 설계 (환자 등록·수정 > "치료정보" 섹션)
```
치료정보   [＋ 항목 추가 ▾]  빠른추가: [고(온)] [고BSD] [싸이] [압노바] [이스카] [메시마] [PJ] [파동] ...
┌────────────┬────────┬─────────────┬──────┬────────────┬──────┐
│ 치료항목    │ 세부    │ 횟수         │ 옵션  │ 메모        │  ✕  │
├────────────┼────────┼─────────────┼──────┼────────────┼──────┤
│ 고주파(온코)│ —      │ 주 [2] → 월 [8]│ 기본 ▾│            │  ✕  │
│ 압노바      │ F ▾ 4단계▾│ 주 [2] → 월 [8]│ 기본 ▾│            │  ✕  │
│ 메시마      │ F ▾    │ 수량 [90] 포   │ —    │            │  ✕  │
│ 페인잼머    │ —      │ 주 [3] → 월 [12]│ 기본 ▾│            │  ✕  │
│   └ 후속치료│ 도수 [1] 림프 [2] 파동 [0] 역박동 [0]   (합 3 = 주 3 ✓)            │
└────────────┴────────┴─────────────┴──────┴────────────┴──────┘
요약 미리보기:  고(온)주2 · 압F4 주2 · 메시마90포 · PJ주3(도1·림2)
[빠른 입력(붙여넣기)] 기존 표기를 그대로 붙여넣으면 위 표로 변환해 보여주고, 확인 필요한 부분을 표시
```
- 주 횟수를 입력하면 월 횟수가 ×4로 자동 채워지고, 직접 고칠 수 있다(월7·월9 등 예외).
- 후속치료 합계가 페인잼머 횟수와 다르면 경고(저장은 가능).
- 항목 종류에 따라 입력칸이 바뀐다(횟수형/수량형/압노바 종류·단계/후속치료).
- 권한: 환자 등록·수정 권한(관리자·스케줄관리자)과 동일. 치료실 담당자는 조회만.
- 모바일: 항목 1개당 카드 1장으로 세로 배치.

## 4. 기존 데이터 전환
1. 파서가 기존 60건의 원문을 **제안**으로 변환(자동 저장하지 않음).
2. 자동 확정 가능한 건과 "확인 필요" 건을 구분해 상담실 검토 목록으로 제공 → 확인 후 확정.
3. 확정 전까지 기존 텍스트 그대로 표시, 확정 시 `plan_raw`에 원문 보존.
4. CSV 가져오기는 기존처럼 텍스트로 들어오면 `plan`에 저장, 구조화는 이후 검토 목록에서 처리.

## 5. 검증 결과 (프로토타입 파서 × 실제 60건)
- **자동 확정 42건(70%) / 확인 필요 17건(28%) / 인식 실패 1건(2%)** — `docs/prototype/plan_parser_result.md`
- 한계로 드러난 유형 (정식 파서에서 보완 필요):
  1. 구분자 없이 이어 붙은 항목(`…*영양제 월1(서비스) 파동 주1(월4)서비스`) → 항목 약어를 문장에서 직접 탐지하는 방식으로 변경
  2. 후속치료의 월 기준 표기(`림(월5),도(월4)`, `(림프)6회,역4회`)
  3. `파동,역박동 (월2회씩S)`처럼 한 옵션이 여러 항목에 걸린 표기
  4. 숫자만 붙은 표기(`싸이2`, `압2`, `압6`, `고(온)4`) 해석 모호
  5. 오타·메모(`얼7`, `통원 치료유지`, `항암후만`)
- 결론: 자유 텍스트를 100% 자동 해석하는 것은 불가능하므로 **구조화 입력이 원천 데이터**가 되고 파서는 이전·입력 보조용으로만 쓴다. 활성 환자가 60명 수준이라 상담실 검토로 전환 가능하다.
- 배포 전 검증 계획: (1) 상담실이 확정한 샘플 20건과 파서 결과 대조, (2) 구조→요약→재파싱 왕복 일치 시험, (3) 권한·저장·스냅샷·CSV 영향 시험, (4) 상담실 시범 입력 후 개선, (5) 문제 시 `plan_raw`·백업으로 즉시 복구.
